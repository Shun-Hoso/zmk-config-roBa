# roBa トラックボール診断

右の球を回し続けてもポインタが十分に動かない原因を調べるための版です。改善用の設定変更は入れていません。感度は400 CPI、読み取り設定は250 Hzのままです。

## 準備するもの

- 私用Mac、右側roBaに接続するUSBケーブル
- `roba-diagnostic.zip` と `roba-restore.zip` をダウンロード・展開したフォルダ
- Python 3（追加ライブラリは不要）

左側の書き換え、分解、入力監視の許可、ペアリングの削除は不要です。診断版ではZMK Studioだけ一時的に使えません。USBをつなぎ、いつも症状が出る接続先・操作モードで試してください。USBを接続していても、選択中のポインタ出力先がBluetoothの場合があります。診断ファイルにその状態も記録します。

## 1. 右側へ診断版を書き込む

1. **右側（球のある側）**をMacへUSB接続します。
2. 右側のリセットボタンを素早く2回押します。
3. Finderに現れる `XIAO-SENSE` または `XIAO SENSE` ドライブへ、`roBa_R-diagnostic.uf2` をコピーします。
4. ドライブが消え、roBaが再起動するのを待ちます。USBはつないだままにします。

`settings_reset` は使いません。左側へこのファイルを書き込まないでください。

## 2. 約90秒、球を操作して記録する

1. Macの「ターミナル」を開きます。
2. `python3` と半角スペースを入力します。
3. 展開したフォルダ内の `collect.py` をターミナルへドラッグし、Enterを押します。
4. 「受信を確認しました」と表示されたら、画面の案内に従います。

| 経過時間 | 操作 |
| --- | --- |
| 最初の5秒 | 球に触れない |
| 次の25秒 | 右の球を同じ方向へ繰り返し転がす。ポインタが止まっても続ける |
| 次の10秒 | 球から手を離す |
| 次の25秒 | もう一度、右の球を繰り返し転がす |
| 残り25秒 | 普段困る細かい操作や大きな移動を試す |

途中で電源を入れ直したりV+Bを押したりせず、まずそのまま記録してください。止めたい場合はControl+Cです。約90秒で自動終了し、同じフォルダに `roba-diagnostic-日時.txt` ができます。

このテキストファイルと、**「今回いつもの症状が出た／出なかった」**だけを共有してください。症状が出なかった記録だけでは原因を確定できません。

Pythonが見つからない、診断データが受信できないなどの表示が出た場合は、その表示を伝えてください。入力監視などの権限を追加する必要はありません。

## 3. 記録後は通常版へ戻す

右側をリセットボタン2回で書き込みモードにし、`roba-restore.zip` 内の `roBa_R-restore.uf2` をコピーします。診断出力がなくなり、ZMK Studioも元の状態に戻ります。キー配置・感度・接続設定の初期化は行いません。

## 保存する情報

右側センサーの通知・読み取り・動きの検出・受け渡しの回数、処理時間、読み取り品質の最小値と最大値、エラー数、USB/Bluetoothの選択状態、スクロールモードかどうかを保存します。生のX/Y移動量、画面上の座標、センサー画像、入力文字、キーコード、画面、アプリ名は保存しません。

ファームウェアの一般ログは無効にし、専用USB端子へ数値の集計だけを出します。収集スクリプトも決められた数値項目の行だけを保存します。外部への自動送信はありません。MacのUSB機器情報は接続先roBaの識別にだけ使い、保存しません。

計測の負荷はゼロではありません。通常版では症状が出るのに診断版では出ない場合も、判断材料として伝えてください。

## 記録の読み方（調査用）

`ROBA_DIAG_V1` で始まる行を約1秒ごとに出します。回数と最大待ち時間は**起動後の累計**です。回数の増分を、操作していた時間帯と照合します。センサーを追加で読み取る処理や、自動リセットは行いません。

| 項目 | 意味 |
| --- | --- |
| `irq / work / done` | センサー通知、読み取り処理開始、終了の回数 |
| `irq_on / irq_pin` | 通知を受け付けているか、通知ピンが現在アクティブか。負値はGPIO読み取りエラー |
| `submit_err / irq_err` | 処理の予約失敗、通知設定の失敗 |
| `reads / moving / zero / read_err` | 読み取り試行、動きあり、動きゼロ、通信エラーの回数 |
| `quality_min / quality_max` | センサーのSQUAL値の範囲。単独で正常・故障を判定する数値ではない |
| `post / post_err` | ZMK入力キューへの受け渡し完了、失敗の回数。XとYを別々に数える |
| `events / frames / filtered` | 入力処理へ到達したイベント、同期イベント、後段へ渡されなかったイベントの回数 |
| `send / send_err` | ポインタレポート送信関数の完了、失敗の回数。PCの受信確認ではない |
| `*_max_ms` | 各段階で完了した処理の最大所要時間。1ms未満は0になる |
| `*_age_ms` | 現在未完了の処理が始まってからの時間。増え続ける段階を調べる |
| `usb / scroll` | USB出力が選択中か、直近の読み取りが球のスクロールモードだったか |
| `seq / ms / span` | 集計番号、起動後時間、集計間隔（ミリ秒） |
| `output_drop` | USBの診断出力が追いつかず送らなかった行数。操作データの損失数ではない |

`reads` 自体が増えなければ、センサーが動きを検出できていないのか、通知が届かないのか、読み取りが待たされているのかを追加の指標と合わせて判断します。`moving` が増える一方で `post / events / send` が追従しない場合は、その間の処理を調べます。読み取り品質の数値やエラーがないことだけで、ハードウェアの正常・故障は断定できません。

## 開発者向け

`Trackball diagnostics` ワークフローが、固定したZMKとPMW3610ドライバーから復元版と診断版をビルドします。計測箇所の追加は隔離したwestディレクトリだけで行い、通常のファームウェアビルドは変更しません。診断版は一般ログの無効化、センサー設定と入力処理の優先度・キューサイズの一致をビルド後に検証します。
